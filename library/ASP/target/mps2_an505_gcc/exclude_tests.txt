# --- M-profile（NVIC + BASEPRI 割込みロック）固有の除外 ---
#
# 【SIL_LOC_INT() 中の svc 発行が HardFault になるケース】
# 本ターゲットの全割込みロック（SIL_LOC_INT＝TOPPERS_disint）は BASEPRI を
# TMIN_INTPRI 相当へ引き上げて実装される。M-profile では SVCall 例外の優先度も
# この BASEPRI でマスクされるため，全割込みロック状態（または同等の高い IPM）で
# 拡張サービスコール（svc 命令）を発行すると SVCall がマスクされて昇格し HardFault
# になる（A-profile は svc が CPSR.I と独立に動くため発行可能だった）。
# → SIL_LOC_INT/CPUロック/高IPM 状態から「拡張サービスコール経由の API」を発行する
#    事前条件のサブケースは本ターゲットでは原理的に成立しない。該当する svc 系
#    api_test は実機実行でハングする可能性があるため，検出され次第ここへ追記する
#    （拡張サービスコールを定義しない大半の api_test は影響を受けない）。
#
# 【タスク例外処理（ena_tex/ras_tex/DEF_TEX）】
# 第3世代カーネル（HRP3 3.4.2）はタスク例外処理機能を持たないため，A-profile/M-profile
# を問わず該当テストは生成されない（プロファイル共通の前提。本ファイルでの個別除外は不要）。
#
# 【データアボート/プリフェッチアボート（EXCNO_DABORT/EXCNO_PABORT）】
# これらは A-profile 固有の CPU 例外番号で，M-profile には存在しない（メモリ保護違反は
# MemManage=EXCNO_MPU(4) として通知される）。api_test/HRP の保護違反系は DEF_EXC の
# 例外番号にターゲット非依存の TTSP_EXCNO_* を用いるため通常は影響しないが，もし
# EXCNO_DABORT/EXCNO_PABORT を直接参照するテストがあればここへ追記する。
# ============================================================================
