このドキュメントの位置付け
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
このドキュメントは，TTG(TOPPERS Test Generator)実行時にオプション指定に
よる設定値の切り替えが，TTC(TOPPERS Test checker)で正しく行われているこ
とを確認するためのテスト仕様書である．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
オプションテスト概要
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
オプションテストとは，configure.yamlにて設定する各オプションの設定値を
デフォルト値から変更した場合に，設定値が変更された内容で出力ファイルが
生成されることを確認するテストである．
なお，各オプションの概要については，\ttsp\tools\common\doc\user.txt参照
のこと．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
オプション一覧
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
本章では，TTG実行時に設定可能なオプションを挙げる．また，オプションテス
ト対象外とするオプションについては，その理由も記載する．

----------------------------------------------------------------------
ターゲットのハードウェアアーキテクチャに関する設定
----------------------------------------------------------------------
・プロセッサ数
  [0より大きい整数]
  ・オプション名 : prc_num
  ・デフォルト   : 4
  ※ TTCバリエーション判別テストのprc_numにて確認済み

・マスタプロセッサID
  [0より大きい整数]
  (メインタスクを起動するプロセッサ)
  ・オプション名 : main_prcid
  ・デフォルト   : 1

・メインタスク用クラス名
  [文字列]
  (初期割付PEがmain_prcidであり，全PEへ割付可能なクラス)
  ・オプション名 : main_class
  ・デフォルト   : TCL_1

・タイマアーキテクチャ
  [local: ローカルタイマ方式， global: グローバルタイマ方式]
  ・オプション名 : timer_arch
  ・デフォルト   : local
  ※ TTCバリエーション判別テストのtimer_archにて確認済み

・システム時刻管理プロセッサID
  [0より大きい整数]
  ・オプション名 : time_manage_prcid
  ・デフォルト   : 1

・割付け可能プロセッサがシステム時刻管理プロセッサのみであるクラス
  [文字列]
  (グローバルタイマー時のタイムイベントハンドラが所属するクラス)
  ・オプション名 : time_manage_class
  ・デフォルト   : TCL_SYSTIM_PRC

・タイマ割込みの割込み優先度
  [文字列か0より小さい整数]
  ・オプション名 : timer_int_pri
  ・デフォルト   : -6

・スピンロックの数
   [0以上の整数]
   (0の場合無制限)
  ・オプション名 : spinlock_num
  ・デフォルト   : 0
  ※ TTCバリエーション判別テストのspinlock_numにて確認済み

・IRCアーキテクチャタイプ
  [local: グローバルIRCのみサポート，global: ローカルIRCのみサポート，
   combination: グローバルIRC，ローカルIRC両方サポート]
  ・オプション名 : irc_arch
  ・デフォルト   : local
  ※ TTCバリエーション判別テストのtimer_archにて確認済み

・APIのget_utmをサポートするか
  [true: サポートする，false: サポートしない]
  ・オプション名 : api_support_get_utm
  ・デフォルト   : true
  ※ TTCバリエーション判別テストのapi_supportにて確認済み

・APIのena_intをサポートするか
  [true: サポートする，false: サポートしない]
  ・オプション名 : api_support_ena_int
  ・デフォルト   : true
  ※ TTCバリエーション判別テストのapi_supportにて確認済み

・APIのdis_intをサポートするか
  [true: サポートする，false: サポートしない]
  ・オプション名 : api_support_dis_int
  ・デフォルト   : true
  ※ TTCバリエーション判別テストのapi_supportにて確認済み

・明示的な割込み要求クリアの有無
  [true: 必要，false: 必要としない]
  ・オプション名 : enable_clear_int_req
  ・デフォルト   : false

・自プロセッサへのプロセッサ間割込みを発行可能なターゲットであるか
  [true: サポート, false: 未サポート]
  ・オプション名 : own_ipi_raise
  ・デフォルト   : true
  ※ TTCバリエーション判別テストのown_ipi_raiseにて確認済み

・CPUロック中にCPU例外が発生しても元のコンテキストに戻れるターゲットか
  どうか
  [true: 戻れる, false: 戻れない]
  ・オプション名 : enable_exc_in_cpulock
  ・デフォルト   : true
  ※ TTCバリエーション判別テストのenable_exc_in_cpulockにて確認済み

・非タスクコンテキストからの割込み優先度マスク変更をサポートしているか
  どうか
  [true: サポート, false: 未サポート]
  ・オプション名 : enable_chg_ipm_in_non_task
  ・デフォルト   : false
  ※ TTCバリエーション判別テストのenable_chg_ipm_in_non_taskにて確認済み

オプションテスト実施と確認内容
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
----------------------------------------------------------------------
マスタプロセッサID (main_prcid)
メインタスク用クラス名 (main_class)
----------------------------------------------------------------------
・デフォルト(main_prcid) : 1
・デフォルト(main_class) : TCL_1

【実施内容】
・configure.yamlのmain_prcidに4を指定
  (もしくはTTG実行の際に，オプション"--main_prcid 4"を指定)
・configure.yamlのmain_classにTCL_4を指定
  (もしくはTTG実行の際に，オプション"--main_class TCL_4"を指定)
・act_tsk_F-c-1-1のTESRYデータを引数に指定してTTG実行

【確認結果】
・生成されたファイルout.c，out.cfgにて，プロセッサIDが4のプロセッサでメ
  インタスクが起動する内容になっていることを確認した

----------------------------------------------------------------------
システム時刻管理プロセッサID (time_manage_prcid)
----------------------------------------------------------------------
・デフォルト : 1
【実施内容】
・configure.yamlのtime_manage_prcidに4を指定
  (もしくはTTG実行の際に，オプション"--time_manage_prcid 4"を指定)
・configure.yamlのtimer_archにglobalを指定
  (もしくはTTG実行の際に，オプション"--timer_arch global"を指定)
・configure.yamlのマクロPRC_TIMER_SELFに4を，CLS_TIMER_SELF_ALLにTCL_4
  を指定
・iact_tsk_F-c-1-1のTESRYデータを引数に指定してTTG実行

【確認結果】
・生成されたファイルout.c，out.cfgにて，プロセッサIDが4のプロセッサでア
  ラームハンドラが起動する内容になっていることを確認した

----------------------------------------------------------------------
割付け可能プロセッサがシステム時刻管理プロセッサのみであるクラス
(time_manage_class)
----------------------------------------------------------------------
・デフォルト : TCL_SYSTIM_PRC
【実施内容】
・configure.yamlのtime_manage_classにTIMER_CLSを指定
  (もしくはTTG実行の際に，オプション"--time_manage_class TIMER_CLS"を指定)
・configure.yamlのtimer_archにglobalを指定
  (もしくはTTG実行の際に，オプション"--timer_arch global"を指定)
・msta_alm_F-a-1.yamlのTESRYデータを引数に指定してTTG実行

【確認結果】
・生成されたファイルout.cfgにて，アラームハンドラが定義されているクラス
  名がTIMER_CLSになっていることを確認した

----------------------------------------------------------------------
タイマ割込みの割込み優先度 (timer_int_pri)
----------------------------------------------------------------------
・デフォルト : -6
【実施内容】
・configure.yamlのtimer_int_priに-4を指定
  (もしくはTTG実行の際に，オプション"--timer_int_pri -4"を指定)
・iras_tex_F-e-2.yaml.yamlのTESRYデータを引数に指定してTTG実行

【確認結果】
・生成されたファイルout.cにて，割込み優先度マスクの値を確認する箇所で，
  -4となっていることを確認した．また，TESRYデータにて，割込み優先度マス
  クをANY_IPM_FOR_TIMER(timer_int_pri + 1)と指定している箇所では，-3と
  なっていることを確認した

----------------------------------------------------------------------

----------------------------------------------------------------------
YAMLファイル読み込みに使用するライブラリ (yaml_lib)
----------------------------------------------------------------------
・デフォルト : kwalify
【実施内容】
・configure.yamlのyaml_libにyamlを指定
  (もしくはTTG実行の際に，オプション"--yaml_lib yaml"を指定)
・本ドキュメントと同フォルダに格納されている，同じ階層にpre_conditionを
  2つ定義しているTESRYデータを引数に指定してTTG実行
  (ファイル名 : yaml_lib_test1.yaml)

【確認結果】
・同じ階層にpre_conditionが定義されていることをエラー検出できないことを
  確認した(YAMLライブラリを用いた場合，同じ値が1つの階層に存在すると上
  書きされてしまう．Kwalifyライブラリを用いれば，エラー検出可能)

【参考情報】
・Kwalifyライブラリを用いた場合，YAMLライブラリを用いた場合よりも細かい
  チェックが可能であるが，若干処理時間が多い
  ・kwalify : 341(秒)
  ・yaml    : 331(秒)
  ※同じ環境で全テストケースを実行時

【確認結果】
・生成されたファイルout.*にて，GCOVを取得するためのソースコードになって
  いることを確認した
