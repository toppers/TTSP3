━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
ターゲット依存関数に関する要件
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
ターゲット依存関数は，以下の3種類に分類される．
・時間操作関数
・割込み発生関数
・CPU例外発生関数

----------------------------------------------------------------------
時間操作関数
----------------------------------------------------------------------
(要件1)
configure.yamlで指定するパラメータall_gain_timeとfunc_time，さらに下記
[時間制御条件]を満たすかどうかの組合せにより，【時間動作判定規約】の判
定結果通りに時間の制御を行うこと．

[時間制御条件]
以下のいずれかの条件を満たす場合trueとする．いずれも満たさなかった場合
はfalseとする．
 (1) 前状態でACTIVATEなタイムイベントハンドラが存在する
 (2) タイムイベントハンドラが登場する(lefttimが指定されている)
 (3) タイムアウト有りのオブジェクト待ちタスクが存在する
 (4) タイムアウト有りの起床待ちタスクが存在する
 (5) 時間経過待ちタスクが存在する(lefttmoが指定されている)
 (6) 処理もしくは後状態にタイムティック指定されている
 (7) ローカルタイマ方式指定時にプロセッサ番号が指定されている周期ハンラ
     が登場する(FMP)
 (8) 前状態において，cycstatにTA_STAが指定されている周期ハンドラが存在
     する

【時間動作判定規約】
all_gain_time，func_timeはconfigure.yamlでtrue/falseを指定し，
gain_timeはvariation属性としてTESRYデータでtrue/falseを指定する．

 No. | all_gain_time | func_time |   gain_time   | 時間制御条件 | 判定結果
 ---------------------------------------------------------------------------
  1  |     false     |   false   |       -       |      -       | ×(※1)
  2  |     false     |   true    |     true      |    true      | ×(※2)
  3  |     false     |   true    |     true      |    false     | ○(※6)
  4  |     false     |   true    | false or 省略 |      -       | ○(※5)
  5  |     true      |   false   | true or 省略  |    true      | ×(※3)
  6  |     true      |   false   | true or 省略  |    false     | ○(※6)
  7  |     true      |   false   |     false     |      -       | ×(※3，4)
  8  |     true      |   true    |     true      |    true      | ×(※2)
  9  |     true      |   true    |     true      |    false     | ○(※6)
 10  |     true      |   true    |     false     |      -       | ○(※5)
 11  |     true      |   true    |     省略      |    true      | ○(※5)
 12  |     true      |   true    |     省略      |    false     | ○(※6)
                                     ※ 表中の"-"はDon't careを意味する．

 ※1 … 時間を操作できないため1件も処理できずエラーとなる．
 ※2 … 時間を制御しないと実現できないテストケース．
 ※3 … 時間を制御できないテストケース．
 ※4 … 時間を止められないテストケース．
 ※5 … 時間を制御して実行．
 ※6 … 時間を流して実行．

----------------------------------------------------------------------
割込み発生関数
----------------------------------------------------------------------
(要件2)
configure.yamlでfunc_interruptに対してfalseが指定された(割込み発生関数
が用意されていない)場合，割込みハンドラや割込みサービスルーチンが登場す
るテストケースは，テスト対象外とされること．また，テスト対象外とされた
テストケースがあった場合に，実行結果として【備考】に示した情報が表示さ
れること．

(要件3)
configure.yamlでfunc_interruptに対してtrueが指定された(割込み発生関数が
用意されている)場合，割込みハンドラや割込みサービスルーチンが登場するテ
ストケースでも，テスト対象とされること．

----------------------------------------------------------------------
CPU例外発生関数
----------------------------------------------------------------------
(要件4)
configure.yamlでfunc_exceptionに対してfalseが指定された(CPU例外発生関数
が用意されていない)場合，CPU例外ハンドラが登場するテストケースは，テス
ト対象外とされること．また，テスト対象外とされたテストケースがあった場
合に，実行結果として【備考】に示した情報が表示されること．

(要件5)
configure.yamlでfunc_exceptionに対してtrueが指定された(CPU例外発生関数
が用意されている)場合，CPU例外ハンドラが登場するテストケースでも，テス
ト対象とされること．

【備考】
・実行結果として表示される情報
  ・入力されたテストケースの総数
  ・実行可能であったテストケースの数
  ・NGテストケースとして除外されたテストケースの数
  ・NGテストケースとして除外されたテストケースのテストIDと除外理由(英語)
  ・総数と除外した数から，実行可能であったテストケースの割合(％)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
要件に対する確認内容
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
時間操作関数のテストに用いたTESRYデータの概要を以下にまとめる(本ドキュ
メントと同フォルダに格納されている)．
・operate_time_x_yyyy.yaml
  ・x    : 要件に記載されている[時間制御条件]の各項目の番号
  ・yyyy : TESRYデータに指定するvariation属性のgain_timeの値
           (省略の場合はnone)
・operate_time_unnecessary_yyyy.yaml
  ・時間操作関数が不要なTESRYデータ
  ・yyyy : operate_time_x_yyyy.yamlのyyyyと同様

割込み発生関数，CPU例外発生関数のテストに用いたTESRYデータは，ttsp/
api_test/配下にある全TESRYデータである．
全TESRYデータの内，割込みハンドラ，割込みサービスルーチンが登場する
TESRYデータは10件，CPU例外ハンドラが登場するTESRYデータは19件である．

(要件1)に対する確認 - 時間動作判定規約 No.1
----------------------------------------------------------------------
【実施内容】
・configure.yamlのall_gain_timeにfalse，func_timeにfalseを指定
 (もしくはTTG実行の際に，オプション"--all_gain_time false --func_time 
  false"を指定)
・以下のTESRYデータを引数に指定してTTG実行
  ・operate_time_x_yyyy.yamlの全TESRYデータ
  ・operate_time_unnecessary_yyyy.yaml

【確認内容】
・TTG(TTC)がエラー終了することを確認した

  に記載されているファイルパスによって確認した)
