このドキュメントの位置付け
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
このドキュメントは，TTC(TOPPERS Test checker)が正しくTESRYデータのエラ
ーを除外していることをチェックするものである．本ドキュメントは，TTCのエ
ラー検査内容をまとめた文書であるcheck_list.txt，param.txt，
vaiation.txtの記載内容を理解していることを前提とする．上記のTTCのエラー
検査内容をまとめた文書の位置は\trunk\ttsp\tools\common\docである．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
エラーチェック概要
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(1)TTCエラーチェッカでは，check_list.txtに記載されている以下の項目に該
   当するエラーチェックを行う．

    ID |    カテゴリ名     |               チェック内容
   ----+-------------------+------------------------------------------
    T0 | environment check | configureの設定
    T1 | basic check       | テストシナリオの構成
    T2 | attribute check   | オブジェクトの属性
    T3 | object check      | オブジェクト内の依存関係
    T4 | condition check   | コンディション内の依存関係
    T5 | scenario check    | テストシナリオ内の依存関係
    T6 | variation check   | バリエーション指定との関係
    T7 | multiple check    | テストシナリオ間の依存関係

(2)T0とT2の項目は規則的にエラーファイル生成が可能のためツールでエラーフ
   ァイルを生成する．生成する項目は以下のように分けられる．

   ・T0: environment check
     - T0_001: configureの設定で記述されていない項目がある
     - T0_002: configureの設定値が指定された型と異なる
     - T0_003: configureの設定値が有効値でない
     - T0_004: マクロの設定値が指定された型と異なる
     - T0_005: マクロの設定値が有効値でない
     - T0_006: 時間操作関数がないのに全テストケース時間停止指定である
     - T0_007: 必要なマクロが定義されていない
     - T0_008: configureがHashでない
     - T0_009: マクロ定義部がHashでない

   ・T2: attribute check
     - T2_001: パラメータの型が想定されている型と異なる
     - T2_002: パラメータの値が有効値でない
     - (*)T2_003: 変数名が命名規則に反している

   (*)の場合は，ツールを用いてエラーファイルを生成するには複雑な処理が
   必要ため，除外する．

(3)T1，T2_003，T3，T4，T5，T6，T7項目のエラーファイルは作成されている．

(4)ASPモードとFMPモードにより扱うTESRYデータが異なる．
   例えば，ASPモードの場合はASPのTESRYデータを，FMPモードの場合はFMPの
   TESRYデータを扱う．その理由は，ASPモードとFMPモードを区別してエラー
   をチェックする必要があるためである．

(5)ASPモードとFMPモードにより実行方法が異なるため，ASPモードとFMPモード
   すべての状態のエラーをチェックする．エラーファイルを生成することと，
   シェルファイルを生成することによりエラーチェックは以下のように分けら
   れる．

   (a)ASPモードでエラーファイル生成し，ASPモードでシェルファイルを生成
   (b)ASPモードでエラーファイル生成し，FMPモードでシェルファイルを生成
   (c)FMPモードでエラーファイル生成し，ASPモードでシェルファイルを生成
   (d)FMPモードでエラーファイル生成し，FMPモードでシェルファイルを生成

(6)ASPモードでエラーファイルを生成するとASPのTESRYデータでエラーファイ
   ルが生成される．ASPのTESRYデータを扱っているため，実行時は(a)と(b)の
   実行ができる．
   FMPモードでエラーファイルを生成するとFMPのTESRYデータでエラーファイ
   ルが生成される．FMPのTESRYデータを扱っているため，実際に(d)しか実行
   ができないが，ASPとFMPに分けられていないTESRYデータにより生成が異な
   る．現在は以下のように分けられている．

   ・FMPモードでもASPのTESRYデータとして生成されるもの
     - ISR
   ・FMPモードのみ生成されるもの
     - SPIN_LOCK

   FMPモードでエラーファイルを生成してASPモードで実行ができるようにした
   理由は，FMPモードでエラーファイルを生成しても，ISRの場合はASPとして
   生成されるため，ASPモードでも実行可能である．さらにFMPモードでエラー
   ファイルを生成した場合にASPモードで実行してもFMPのTESRYデータは除外
   されるため問題はない．

ファイルの生成およびファイルの削除について
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
----------------------------------------------------------------------
エラーファイル
----------------------------------------------------------------------
・エラーファイルは，TTC実行時にエラーになるはずのTESRYデータおよび
  configure.yamlファイルを意味する．

・エラーファイル生成時にエラーファイルはツール実行ファイルのフォルダに
  生成される．さらに生成されたエラーファイルの全リストをファイルとして
  ツール実行ファイルのフォルダに保持する．そのファイル名は
  make_file_list.txtである．

・エラーファイルの生成は実行位置に関係なくどこでも生成可能である．

----------------------------------------------------------------------
シェルファイル
----------------------------------------------------------------------
・シェルファイルは，生成されたエラーファイルを簡単に実行できるようにす
  るためのシェルファイルである．

・シェルファイル生成時にシェルファイルは実行したフォルダに生成される．
  さらに生成されたシェルファイルの全リストをファイルとしてツール実行フ
  ァイルのフォルダに保持する．そのファイル名はmake_file_list.txtである．

・シェルファイルの生成は実行位置に関係なくどこでも生成可能である．

----------------------------------------------------------------------
ファイル削除
----------------------------------------------------------------------
・削除時はファイルを生成する際に共に生成されたmake_file_list.txt内のフ
  ァイルリストを参照して削除を行う．その理由は生成されたファイル以外の
  ユーザーのファイルが削除されることを避けるためである．
  したかって，削除時にmake_file_list.txtファイルが存在しない場合は削除
  が不可能になるが，その場合はmake_file_list.txtファイルを改めて生成す
  ることにより削除が可能になる．さらに削除するとmake_file_list.txtファ
  イルも削除される．

・ファイル削除は実行位置に関係なくどこでも削除可能である．

ツール使用方法
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
----------------------------------------------------------------------
プロファイルのオプション
----------------------------------------------------------------------
・ASP
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -a ・・・

・FMP
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -f ・・・

----------------------------------------------------------------------
ファイル生成のオプション
----------------------------------------------------------------------
・エラーファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -f -c ・・・

・シェルファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -f -s ・・・

----------------------------------------------------------------------
エラーファイルの生成
----------------------------------------------------------------------
・ASPモードでT0の全項目のエラーファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -a -c -t 0

・FMPモードでT0の全項目のエラーファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -f -c -t 0

・T0項目内の細部項目のエラーファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -a -c -t 0 -l 1
    * -l オプションは1から6まで指定可能
    * -l 1 はT0_001を意味し，-l 6 はT0_006を意味する

・ASPモードで全項目のエラーファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -a -c -A

・FMPモードで全項目のエラーファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -f -c -A

----------------------------------------------------------------------
シェルファイルの生成
----------------------------------------------------------------------
・シェルファイル生成はすべての項目で可能である．

・ASPモードでT1の全項目のシェルファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -a -s -t 1

・FMPモードでT1の全項目のシェルファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -f -s -t 1

・T2項目内の細部項目のシェルファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -a -s -t 2 -l 1

・ASPモードで全項目のシェルファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -a -s -A

・FMPモードで全項目のシェルファイル生成
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -f -s -A

----------------------------------------------------------------------
生成したファイルおよびフォルダの削除
----------------------------------------------------------------------
・削除は生成したすべてのファイルおよびフォルダを扱う．

・生成したファイルおよびフォルダの削除
  /trunk/ttsp/tools/ttc/test/err_check/error_checker.rb -r

エラーチェック方法
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
・エラーチェッカは，エラーファイルからシェルファイルを作出し，作出した
  シェルファイルを実行することによりエラーチェックができる．以下はエラ
  ーチェックの順である．

  (1)T0またはT2のエラーチェックが必要な場合，T0またはT2のエラーファイル
     を生成する．T2_003はすでにエラーファイルが作成されている．

  (2)生成したT0とT2のエラーファイルからシェルファイルを生成する．または，
     作成されているT1，T2_003，T3，T4，T5，T6，T7のエラーファイルからシ
     ェルファイルを生成する．

  (3)生成されたシェルファイルを実行してエラーをチェックする．
