# FMP カバレッジ計測記録（BBテスト）

> FMP用のWBテスト（方式2）は未作成のため，`all` モード＝`bb` モードと等価。
> 本ファイルはBBテスト（API auto-code 20分割 + check_library）のみでの計測結果を記録する。
> → 未到達分岐の分析は [WB_UNREACHABLE.md](WB_UNREACHABLE.md) を参照。

---

## 計測条件

| 項目 | 値 |
|---|---|
| カーネル | FMP3 (`../fmp3/`) |
| ターゲット | zybo_z7_gcc (Cortex-A9 dual-core, QEMU) |
| スクリプト | `scripts/coverage_gcov_fmp.sh all` |
| モード | all = check_library + API auto-code 20分割（WBテスト無し） |
| ビルドフラグ | `ENABLE_GCOV=true`, `-DNDEBUG` (COPTS), `-O2` (Makefile既定) |
| フィルタ | `/fmp3/kernel/` のみ集計 |
| 計測日 | 2026-06-09 |

### コンパイルオプション補足

| フラグ | 効果 |
|---|---|
| `ENABLE_GCOV=true` | `-fprofile-arcs -ftest-coverage` を追加，gcov 計装有効 |
| `-DNDEBUG` | `assert()` マクロを無効化。`t_stddef.h` の `#ifndef NDEBUG` で制御される assert 分岐がコードから除去され，計測対象から外れる |
| `-O2` | コンパイラ最適化有効。`static inline` 関数が呼び出し元に展開され，同一ソース行が複数箇所で計測される（`wait.h` の 64 分岐などはこのアーティファクト） |

## ASP との比較

| 指標 | ASP (all) | FMP (all) |
|---|---|---|
| 総分岐数 | 1459 | 1677 |
| 到達分岐 | 1434 | 1575 |
| カバレッジ | 98.3% | 93.9% |
| 未到達分岐 | 25 | 102 |

FMPはASPに対し分岐数が218増加（+14.9%）。増加分の主要因：
- FMP固有機能: spin_lock.c（38分岐），マルチコア協調処理（interrupt.c等に多数追加）
- サブ優先度機能: task.c, task_manage.c, mutex.c の関連分岐
- 非TM processorパス: time_event.c, startup.c

## WBテスト候補

現状FMPのWBテストは存在しない。未到達分岐のうちWBテスト化が検討できるものは [WB_UNREACHABLE.md](WB_UNREACHABLE.md) §2, §6 を参照。ただし主要な未到達分岐の多くはマルチコア並行実行シナリオに起因するため，単純なWBテスト追加では到達困難（マルチコアタイミング依存）。
