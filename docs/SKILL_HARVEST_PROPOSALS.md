### 提案1：カバレッジ計測の方法論（新規 reference）

- **対象skill**：`toppers-kernel-debug` に新規 `references/coverage-methodology.md`
  （検証・計測の領域。SKILL.md §3 付近からリンク）。
- **要旨**：適合性テストの**分岐(C1)カバレッジ**を、カーネル無改変のまま測り、
  「100%を追わず**残存分岐を分類して台帳化**する」までを一連の作法として説明する。
- **追記案の骨子**（すべて実装非依存）：
  1. 防御パスが踏まれたかの証明には**行(C0)では不足・分岐(C1)が要る**。
  2. 計測二系統と棲み分け：**非侵襲（実行トレース＝基本ブロック）→ C0のみ・再ビルド不要**／
     **計装ビルド → C1可・ただし合否用バイナリと計測用バイナリを分離**（＝カーネルread-only維持・
     合否は無計装版、カバレッジは計装版でのみ算出）。
  3. **忠実な分岐対応付け**：インライン展開は分岐数を水増しし、`assert` は構成依存の分岐を増やす。
     **インライン抑制＋アサート無効化**でソース論理どおりの分岐に揃える。
     〔ツール依存：コンパイラのインライン抑制・アサート無効マクロ。固有フラグ名は本文に書かない〕
  4. **union（複数テストの合算）安全則**：合算前にクリーン再ビルド。古い計装メタが混ざると
     分母が揺れ、再コンパイル差を「カバレッジ向上」と誤認する。
  5. **残存分岐の分類（最重要）**：未達を放置せず**到達不能台帳**に各1分岐の理由を記す。3類型＝
     (a)**構造的dead／防御コード**（当該構成で常真の検証・`#if`除外アーム・非復帰呼出しの後続）、
     (b)**並行/タイミング依存**（実レース・マルチコア交錯でのみ到達＝別途実証し、根拠付きで
     union から除外）、(c)**機能/ターゲット依存ゲート**（既定ターゲットに無い能力が必要。例：
     64bit時刻の折返しに**シミュレーションタイマ**）。乖離台帳と同じ規律（`toppers-kernel-dev`へ相互リンク）。
  6. **config依存の防御分岐へ届かせる**には、カーネル定数の**ビルド時上書き**が要ることがある。
     その際は #ifndef ガード／既定不変パターン（禁則①・`toppers-kernel-dev` 相互リンク）で、
     **計測ビルド専用**に適用し patch 化、通常・CI ビルドは無改変版のままにする。
- **分類**：カバレッジ計測の方法論。
- **プロセッサ**：非依存（ツール依存：計装コンパイラ／実行トレーサ）。
- **出所リポ**：TTSP3（FMP3 計測：`docs/FMP/BB_UNREACHABLE.md` ほか）。
- **実装非依存の根拠**：固有スクリプト名・フラグ名・ファイル名を含まず、概念（C0/C1・侵襲/非侵襲・
  union再ビルド・残存分類・ビルド時上書き）のみ。別RTOS派生でも同じ作法が通る。

### 提案2：生成式 適合性スイートの仕組み（既存 reference へ追記）

- **対象skill**：`toppers-kernel-debug` 既存 `references/conformance-ttsp3.md` に節を追加。
- **要旨**：適合性テストが**機械可読なテスト仕様データから生成**される前提と、
  **チェックポイント列**による合否判定、異常系の作り、版差での**テスト削除**規律を加える。
- **追記案の骨子**：
  1. テストは**仕様データ→自動生成**（手書きでない）。よって網羅の穴は多くが**仕様データの穴**＝
     カーネルを編集せず**仕様エントリ追加**でカバレッジを上げる。
  2. 二方式：**ブラックボックス（仕様から自動生成）**が大半、**ホワイトボックス（手書き）**が
     生成では届かない**特定の防御分岐**を狙う。カバレッジは方式別（自動のみ／自動+手書き）に出す。
  3. **判定オラクル＝順序付きチェックポイントログ**。成功＝終端マーカー（全点通過）。
     途中停止は**最後に到達した点**で故障箇所を局所化。失敗マーカーは
     「アサート失敗／値不一致／想定外エラーコード／順序外」を区別する。
     「通るはず」で判定しない＝**ログの実測が根拠**。
  4. **異常系エントリは特定の検証分岐を意図的に駆動**（引数範囲・不正ID・コンテキスト・
     CPUロック中・ディスパッチ禁止中）。検証の**短絡されないアーム**に届かせるには、
     先行句で短絡されない入力を選ぶ。
  5. **構成エラー（静的API）テストは「失敗するはず（コードE_x）」しか表現できない**＝
     「成功するはず」を表せない。よって**上流が検証を削除**したら、対応する異常系テストは
     **修正でなく削除**し、**乖離台帳に「意図的削除」と記録**する（提案3-下と相互リンク）。
  6. **RESULT と VERDICT の区別**：厳密合否（全ビルド+全テスト通過）と、
     **退行ゲート**（緑数 ≥ 既知差を許容する基準値）。既知の許容失敗が真の退行を覆い隠さないための分離。
  〔TESRY/生成器/チェックポイント等の固有名は注記のみ。本文は概念に留める〕
- **分類**：テスト生成の方法論／診断・検証。
- **プロセッサ**：非依存。
- **出所リポ**：TTSP3（`AGENTS.md`・`docs/GLOSSARY.md`）。
- **実装非依存の根拠**：「仕様駆動生成・チェックポイントオラクル・異常系の短絡回避・
  否定テストは削除して台帳化・厳密合否と退行ゲートの分離」はどの生成式スイートにも通じる。

### 提案3：マルチプロセッサ（FMP系）派生のテスト概念（新規 reference か節追加）

- **対象skill**：`toppers-kernel-debug` に `references/multiprocessor-testing.md`（新規）か、
  `conformance-ttsp3.md` に「派生差がテスト設計に効く」節。AGENTS.md §7 の「FMP=マルチ」を深掘り。
- **要旨**：単核RTOSとの差が**カバレッジ・テスト設計**に効く点をまとめる。
- **追記案の骨子**（実装非依存・固有名は出さない）：
  1. **SMPで分岐カバレッジが下がる理由**：多くのAPIに「**遅延ディスパッチ／PE間**」アームが付き、
     逐次・単核テストでは踏めない。**実2コアのストレステストで実証**するか、
     **タイミング依存・到達不能として台帳化**する。
  2. **時刻管理にはタイムマスタPEがあり、時間イベント非処理PEは自分のイベントをマスタへ転送**する。
     転送分岐は「あるPEが時間イベント非処理」のときだけ存在＝そういう**構成**で初めて到達。
  3. **割込み識別子はPEアフィニティを内包**（割込み番号が対象PE＋ローカルマスクを符号化）。
     「別PE宛」の異常系テストが**アフィニティ検証アーム**を踏む。
  4. **割込みコントローラ方式（ローカル/グローバル/複合）が、どの異常系テストが適用・
     どのエラーを期待するかをゲート**する。ある方式向けの否定ケースは別方式ターゲットで**除外**され、
     **カバレッジに現れない**点に注意（ターゲット毎に監査）。
  5. **PE間観測には同期点が要る**：他PEが起こした状態変化を観測するには、
     IPI／全体ロックが落ち着くようバリア／遅延を挟んでから検証する。
  6. **サブ優先度**：ある優先度を「サブ優先度有効」に設定でき、実行可能タスクのサブ優先度変更は
     同一優先度群内で**並び替え**（キュー位置として観測）。シーリングミューテックスで**昇格**した
     タスクはサブ優先度が最上位にクランプ。これらは「サブ優先度を実際に構成＋同一優先度の複数タスク」
     があって初めて踏める分岐。
- **分類**：マルチプロセッサ（FMP）概念／診断・検証。
- **プロセッサ**：非依存（マルチコアRTOS一般。例示はARM Cortex-A9 SMPだが概念は非依存）。
- **出所リポ**：TTSP3（FMP3：`docs/FMP/BB_UNREACHABLE.md`・`docs/GLOSSARY.md`）。
- **実装非依存の根拠**：タイムマスタ転送・割込みアフィニティ・IRC方式ゲート・PE間同期・
  サブ優先度並び替えは、SMP RTOS一般のテスト設計に通じる概念。固有マクロ名は本文に出さない。

### 提案4（小・任意）：版差におけるテストオラクルの不安定性

- **対象skill**：`toppers-kernel-dev` 既存 `references/upstream-merge.md` に短く追記
  （cfg/テスト追従の観点）。または提案2-5 に内包して一本化（キュレーター判断）。
- **要旨**：仕様版が上がると**否定テストの期待が変わる/消える**。エラーコード変更は仕様データ更新で

- **プロセッサ**：非依存。

- **実装非依存の根拠**：「否定テストはエラーコード差なら更新・検証削除なら削除し台帳化」は
  どの版付きAPIスイートでも通じる規律。

### 提案5：SMPレース不具合の「決定的再現」法（既存 reference へ追記）

- **対象skill**：`toppers-kernel-debug` 既存 `references/multiprocessor-testing.md` §1
  「届かせ方」に具体技として追記（または `debugging-playbook.md` に「レース再現」節）。
- **要旨**：時間依存のSMPレース不具合を、カーネル無改変方針を守りつつ**決定的に再現**し、
  かつ**観測差を当該修正のみに帰属**させる作法。
- **追記案の骨子**（すべて実装非依存）：
  1. **最小リバート差分による帰属**：修正済みカーネルから「当該1ファイルの修正だけ」を戻して
     before版を作る。`diff` が最小になるので、観測した挙動差（ハング/アサート ⇄ 正常）が
     **その修正のみに帰属**することを保証できる。before/after を1ディレクトリに同梱し、
     別ビルドフォルダでビルド＝**再現環境を自己完結化**（第三者が1コマンドで両挙動を再現）。
  2. **自己マイグレーション往復（リーダレス）でPE間再ディスパッチを高頻度駆動**：
     「発行側タスクが被害側を起こす」構図は同一PE上で**優先度スターベーション**を生み、
     偽のハング（被害側が走れず）になりやすい。代わりに**複数タスクが各自を周期的にPE間移送**
     （自タスクのアフィニティ往復）すると、同一PEの優先度衝突なしに**PE間の再ディスパッチ枝を
     高頻度で駆動**でき、遅延ディスパッチ／PE間スレッド切替えの競合に確実に届く。
  3. **被害側の優先度・本数設計**：移送タスクは中位優先度・複数本、制御/集計タスクは別優先度で
     用意し、busy-loop で計測役を飢えさせない（飢餓は偽陽性の温床）。
- **分類**：テスト設計/SMPレース再現。
- **プロセッサ**：非依存（マルチコアRTOS一般）。
- **出所リポ**：TTSP3（FMP3 POSIXポート）。
- **実装非依存の根拠**：最小リバート帰属・リーダレス自己移送・飢餓回避はどのSMP RTOSでも通じる。
  固有のタスク名・cfg・スクリプトは本文に出さない。

### 提案6：ホストシミュレーション移植（POSIX等）のデバッグ着眼（新規 reference）

- **対象skill**：`toppers-kernel-debug` に新規 `references/host-simulation-port.md`
  （または `observing-execution.md` に「ホスト移植の二層観測」節）。SKILL.md §1 付近からリンク。
- **要旨**：RTOSを**ホストOS上で擬似実行する移植**（タスク＝ホストスレッド）に特有の、
  単核実機には無い故障モードと観測の着眼。
- **追記案の骨子**（実装非依存・固有名なし）：
  1. **ディスパッチ決定と実行担体の切替えが分離**：ホスト移植では「全体ロック下のスケジュール
     決定」と「実行担体（ホストスレッド）の suspend/resume」が別物。
     **ロック解放→自スレッド suspend の窓がホストOSのプリエンプションに晒される**＝ここが
     SMPレースの温床。観測も**カーネル決定層とスレッド切替え層の二層**で時系列を突き合わせる。
  2. **PE固有アイデンティティの汚染**：PE識別子等を「他PEが上書きしうる制御ブロック」から
     読むと、別PEの値を掴む（**TLS/per-PE汚染**）。**自PEに固定された制御ブロックから渡す**のが
     鉄則。間欠ハング・想定外アサートの典型原因＝「正しい値だが読む場所が他PEと共有」を疑う。
  3. **ホストシグナルの乗っ取り**：ホスト移植は終了系シグナル等を内部用に転用しうる。
     よって**ハングしたプロセスは通常の終了シグナルで殺せず、強制（catch不能）シグナルが要る**。
     テスト/CIのタイムアウト殺しはこれを前提にする（さもないと「殺したはず」が残存）。
  4. **predicate ベースの待ち**：条件変数等の待ちは「起こされたか」フラグではなく**述語**で
     判定し、**lost-wakeup**（条件成立の通知を取りこぼす）に耐える。
- **分類**：観測・デバッグ/ホストシミュ移植。
- **プロセッサ**：非依存（POSIX/Windows等、ホスト上で擬似実行する移植一般）。
- **出所リポ**：TTSP3（FMP3 POSIXポート）。
- **実装非依存の根拠**：決定/担体分離・per-PE汚染・シグナル乗っ取り・predicate待ちは
  ホスト擬似実行移植に普遍。固有のアーキ名・API名・シグナル名は本文に出さない（注記のみ）。
